```

/sim_mode_a  /sim_mode_b  /code_crimson  /code_red
```

호출 형식: `ros2 service call <서비스> std_srvs/srv/Trigger`

| 영상 1 — **OFF, 모드 A** | `meet_pass_enabled: false` → **t=26.6 에 공급(C05)·회수(C08)가 2F 동측 가지에서 정면 대치**(양쪽 다 정지), 이후 **t=88.2 DEADLOCK** 빨간 배너 (당사자 `C05@B2-06`, `C08@B2-07a`) | "교행 규칙을 끄면 마주 오는 두 카트가 26초에 서로를 막습니다. 관제는 **전 캡슐이 멈춘 뒤 20초**를 세어 대치 당사자 명단과 함께 알람을 냅니다" |
| 영상 2 — **OFF, 모드 B** | 선점을 켜도 **똑같이 t=26.6 에 같은 자리에서 대치** — 배너만 **t=96.5** 에 뜸 (같은 당사자) | ⭐ **"선점을 켜도, 같은 순간 같은 자리에서 막힙니다.** 두 카트 모두 P3라 우선순위로는 누가 비킬지 정할 수가 없습니다 — 스케줄링이 손댈 수 있는 문제가 아닙니다" |
| 영상 3 — **ON (기본값)** | `meet_pass_enabled: true` 원복 → 양 모드 모두 완주 (**A 74.97 / B 86.77**), 같은 t=26.1 에 `MEET_PASS` | ⭐ **"계층이 다른 문제는 계층이 다른 규칙으로 풉니다.** 막혔던 그 순간 그 자리에서, 교행 루프 하나로 양쪽 다 통과합니다 — 이것이 배차·경로·교통제어·긴급대응을 나눠 설계한 이유입니다" |

> **배너 시각이 A 88.2 / B 96.5 로 다른 이유** (질문 대비): 대치가 시작된 시각은 **양 모드 모두 t≈26.6 으로 같습니다.**
> `DEADLOCK` 은 **전역 무진행 20초** 기준이라, 다른 캡슐이 언제까지 움직였는지에 따라 배너 시각만 달라집니다 —
> 모드 A 는 마지막 도착이 P0 68.2초, 모드 B 는 RTA 회복 중이던 P2 76.5초였고 각각 +20초에 배너가 떴습니다.
> **선점이 교착을 늦춘 것이 아닙니다** (선점을 켜도 교착 시점은 동일). 나머지 세 오더는 양 모드 모두 교착과 무관하게 완주합니다.

🔴 **녹화 종료 후 `meet_pass_enabled: true` 원복 필수** — false 로 남으면 2부 교행 장면이 사라지고 시연이 교착합니다.
(`kpi_report.py` 는 yaml↔코드 불일치를 잡지만, **양쪽 다 false 면 통과**하므로 눈으로 확인하세요.)
