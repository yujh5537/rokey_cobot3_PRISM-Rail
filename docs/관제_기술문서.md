# 관제 코어 기술 문서 (v1.3 — v3.6 최종 수치판) — A. 관제 코어 (남현지)

> 인터페이스 정본은 `rail_bridge/interface_schema.json` (v3.3-FROZEN-2026-08-23) 단일 기준.

의료 레일 배송 디지털 트윈의 관제 서브시스템. 병원 2개층 30개 블록 위 캡슐 10대를
30Hz로 관제하며, P0(Code Crimson) 대량수혈 프로토콜의 **우선순위 선점**을 핵심 시연으로 한다.

## 1. 한 문장 요약

> 선착순(FCFS) 관제에서 **꼴찌(71.2초)** 였던 응급 혈액 콘보이(4대 → OR2 집결)를 선점(PEDD) 관제가 **5.8% 앞당기고**,
> 간섭이 없는 오더(멸균 공급)는 **양 모드 동률 36.2초로 손대지 않으며**,
> 양보로 지각 위기에 몰린 정시 화물(P2)은 **RTA 회복 제어가 스스로 가속해 마감 내 정시 도착**시키며,
> 단선에서 마주 오는 캡슐은 **교행 규칙(R13)으로 스쳐 보내** 교착 자체가 성립하지 않게 한다.

## 2. 아키텍처 — 포트·어댑터 3계층

```
[Isaac Sim 씬(B)] ←프림 트랜스폼─ [브릿지(C)] ←/capsule_pose(30Hz)─┐
[웹 대시보드(D)] ←/block_state, /order_event ────────────────────┤
                                            [node.py  (rclpy 어댑터)]
                                            [bridge.py (제어·페이로드, ROS 무관)]
                                            [control_core (관제 엔진, 순수 Python)]
```

- **진실 소스는 관제 코어**: 캡슐 위치(블록id + 진행거리 + 방향 + xyz)를 코어가 계산·발행,
  씬과 UI는 구독만 한다. 좌표 변환 로직은 `geometry.py` 한 곳(발행원 반올림 원칙 포함).
- rclpy 의존부를 어댑터로 격리 → ROS 없이 전 로직 테스트 가능, 통합 장애 시
  "브리지 테스트 통과 여부"로 관제/연동 책임 즉시 분리.

## 3. 3FSM — 상태 기계 3종

| FSM | 상태 | 비고 |
|---|---|---|
| 오더 | CREATED → EN_ROUTE → ARRIVED → DONE | P0는 4캡슐 슈퍼오더 (전원 도착 시 ARRIVED) |
| 캡슐 | DOCKED/QUEUED/STANDBY → MOVING ↔ YIELD_WAIT/EVACUATED/FINISHING → UNLOADING → REMOVED | |

## 4. 알고리즘 5계층

| 계층 | 채택 | 탈락 대안과 이유 |
|---|---|---|
| ① 배차 | PEDD(우선순위→EDD) + 콘보이 슈퍼오더 | 단순 FIFO: 응급 역전 불가 |
| ② 경로 | 정적 경로 테이블 | WHCA*/CBS: 트리형 토폴로지라 경로가 유일 — 탐색할 것이 없음 |
| ③ 교통 제어 | 철도식 폐색: 블록 상호배제 + 차두간격 + **회랑 방향 토큰** + 단방향, **CC 중 콘보이 한정 용량 개방(R9 개정 — 이동 폐색 방식)**, **교행 루프(R13, v3.6 — 대향 시 쌍둥이 레인 치환)** | 은행원 알고리즘: 더 복잡하면서 이 구조에선 이득 없음 / 콘보이까지 블록 1대 고정: 4대가 직렬화돼 파도가 길어짐(실측 −5.8% → −3.6%로 후퇴) |
| ④ 긴급 대응 | **ETA 이동 파도 선점** + 3분기 스윕 + 롤링 해제 | 전 경로 일괄 잠금: 원거리 하위 오더까지 과잉 지연(P1 2배 지연 실측) |
| ⑤ 속도 (R11/R12) | **RTA 슬랙 회복**(샤프트 고정시간 분해 + 지령 래치) + 회복 불가 시 **P2→P1 자동 승격** | 단순 비례식: just-in-time 수렴으로 여유 0 / MPC: 30블록 MVP엔 과설계 |

### 4-1. 이동 파도(bow-wave) 선점 — 장면 ①②③의 단일 원리

P0 발령 시 콘보이의 **잔여 경로 중 ETA 15초 이내 블록만** 잠근다(파도는 콘보이와 함께
전진, 지나간 블록은 자동 해제). 파도를 만난 하위 캡슐은 3분기로 처리:

1. **양보 (R2/R5)** — 파도 밖에 있으면 진입 보류. 단, 내 위치(블록/회랑)가 상위 경로에
   걸치면 양보 대신 전진해 비운다(제자리 대기가 상위를 막는 역효과 방지).
2. **완주 허용 (R4)** — 파도와 **같은 방향**이면 잠금 블록으로의 탈출 전진(플러시) 허용.
   실측: P1은 파도 위에서 완주 허용으로 통과해 선점 상황에서도 손해 0(양 모드 동률 37.6초)
   — 세우지 않는 것 자체가 성능이다.
3. **대피 (R3)** — 파도와 **역방향**이면 ①루프 대피 레인 치환(EVAC_LANE) ②빈 지선 왕복
   회피(EVAC_SPUR, 상위 목적지 지선은 제외) 순으로 회피. 지선 내 저속 후진만 허용(제자리 리버설).

R6(미발령 오더 잠금 제외 — 예지 금지), R8(안전망: 모드와 무관하게 항상 적용).

## 5. 시연 시나리오와 수치 (토폴로지 v3.6 = v3.5 + 멸균 공급/회수 쌍 + R13 교행, 30Hz, 결정론 검증)

발령: P2=1s, P1=2s, **P3 멸균 공급=2s**, **P0=8s**, **P3 기구 회수=17s** · 시연 due: P0=30 / P1=40 / **P2=77** / P3=130 s
속도(A1 체계): 수평 평시 1.0 / 회복 상한 2.0 / 샤프트 0.5 / 곡선·분기 0.5 m/s (가속 ≤0.8 m/s² — 용혈 방지)
**등급→속도 매핑**: P0·P1 = 상시 2.0 (‘즉시’·‘최대한 빨리’) · P2 = 1.0 + 필요 시 RTA 회복 (‘정해진 시간 내’)
· P3 = 0.7 고정 (‘완수’ — 멸균 물품·사용 기구 적재 안전 저속)

| 오더 | 모드 A (FCFS) | 모드 B (선점+RTA) | 해석 |
|---|---|---|---|
| **P0 혈액 콘보이 4대 → OR2** | 71.17 s (**꼴찌**) | **67.07 s** | **−5.8%**, 꼴찌 탈출 — 헤드라인 ① (OR2 지선 순차 도킹 56.6/60.1/63.6/67.1) |
| P1 응급약품 | 37.60 s | 37.60 s | 동률 — 양 모드 공통 v_max (정직 표기) |
| P2 항암제 | 48.43 s | 76.60 s | 양보 비용. **헤드라인 ②: RTA 회복으로 due 78초에 1.40초 여유 정시** |
| **P3 멸균 공급 (O-1)** | 36.17 s | **36.17 s** | **동률 — 콘보이와 동방향이라 무간섭.** 헤드라인 ③: "선점은 필요할 때만 개입한다" |
| P3 사용 기구 회수 (O-5) | 54.77 s | 85.77 s | 대피 비용, 장면 ③ = B2-04b 레인 치환(`EVAC_LANE` t=32.9 → `RESUME` t=72.0) |

모드 A 도착 순서는 선착순(공급→P1→P2→회수→P0), 모드 B는 공급→P1→**P0**→P2→회수.
공급(O-1)이 양 모드에서 먼저 끝나는 것은 순서 위반이 아니라 설계다 — **우선순위는 간섭을 겪은
오더들 사이에서만 지연을 배분**한다(회귀 단언: `P1 < P2 < 회수`). "중요한 것부터, 단 필요할 때만".

**헤드라인 ② 대조군 실측**: RTA 회복을 끄면 P2 는 79.27 초 도착 = **1.27초 지각**.
켜면 76.60 초 = 1.40초 여유. 회복 효과 2.67초. "선점은 공짜가 아니다 → 그러나
시스템이 스스로 만회한다" 가 숫자로 닫힙니다.

## 6. 안전·품질 검증 (테스트 25종 = 회귀 13 + 브리지 7 + 엣지 5, `pytest src/rail_control_core/test`)

- **R8 불변식 전수 검사**: 매 틱 30블록 × {용량 초과, 정면 대치, 역주행, 추월, 구간 이탈}
  — 시연·폭주 전 시나리오에서 **위반 0건** (안전은 모드와 무관하게 보장)
- **회귀 기준값 고정**: 기준값 ±0.2s 이탈 시 테스트 실패 → 성능 회귀 즉시 감지.
  순수 파이썬 측정값 85.77s 가 실기 ROS 노드 실행에서 그대로 재현됨
  (`[SIM_DONE] sim makespan=85.77`, 30Hz 발행 실측 29.99Hz — 관제 결정론 입증)
- **R13 교행 회귀 방지**: 초판 R13 은 거부 사유 문자열(`headon`)로 게이트를 걸어 용량 1 본선에서
  한 번도 발화하지 않는 죽은 코드였다(사유가 항상 `capacity` 로 먼저 잡힘). 지금은 OFF/ON 대조
  테스트가 **OFF 시 반드시 교착**함을 확인하므로, 규칙이 다시 죽으면 테스트가 실패한다
- **발행원 반올림**: 전 좌표 소수 4자리 불변식 (부동소수 잔재 재발 방지)

**설계상 한계 (정직 고지)**: ① 교행 자산(쌍둥이 레인)이 없는 구간의 정면 대치는 해소가 아니라 감지·통보까지가 범위
(FCFS의 본질적 한계이며, 이것이 선점 관제의 존재 이유) ② 하역 후 회송·디포 재충전은
시연 범위 외 ③ 경로 유일 가정 — 레일 증설 시 계층 ②를 탐색형으로 교체 필요
④ 캡슐 고장 대응 — 고장 캡슐을 EVACUATED 고정으로 두면 폐색 규칙이 해당 블록을
우회 불가 자원으로 처리하고 DEADLOCK 감지가 후속 정체를 통보하는 데까지는 동작하나,
회수 오더 자동 생성은 미구현(향후 과제) ⑤ **감속은 즉시 근사** — 가속만 0.8 m/s²로 제한하고
감속은 즉시 적용한다(과속 진입이 생기지 않는 보수적 방향의 근사)
⑥ **곡선 감속은 꺾임점 ±0.4 m 존 근사** — 실제 코너 반경(r=0.22)을 적분하지 않는다.
